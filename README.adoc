= gesinn-it-docs-master-pub

Centrally maintained, reusable https://en.wikipedia.org/wiki/AsciiDoc[AsciiDoc] building blocks for consistent documentation across repositories.
Included as a Git submodule; content is referenced via AsciiDoc `include::` directives and assembled by CI into generated output files.

== Concept

Three content levels:

* `snippets/` — atomic blocks, *no heading*, inline-embeddable
* `sections/` — standalone sections with a `==` heading (Level 2)
* `documents/` — full document templates that assemble sections and snippets

Each level is organized by scope:

* `universal/` — technology-agnostic content (SemVer, Conventional Commits, admonitions)
* `mediawiki/` — MediaWiki extension repositories
* `ansible/` — Ansible role repositories

Heading convention: all sections and documents use `==` (Level 2).
Consumers control embedding depth via `[leveloffset=+1]` at the `include::` site.

When embedding a `sections/` file under an existing `==` heading in a document, always use `[leveloffset=+1]`:

[source,asciidoc]
----
== Step 5: Commit your changes

\include::sections/universal/conventional-commits-policy.adoc[leveloffset=+1]
// renders as '=== Conventional Commits Policy' — one level below the step heading
----

Snippets that are always included as a group (e.g. one per language) begin with `'''` followed by a bold title.
This provides visual separation without introducing a heading level:

[source,asciidoc]
----
'''

*Coding Conventions — PHP*

Tooling: ...
----

== Consumer repository layout

The recommended structure for a consumer repository:

----
repo/
├── README.adoc                          ← generated
├── README-source.adoc                   ← source
├── docs/
│   ├── attributes.adoc                  ← project attributes (single source of truth)
│   ├── CONTRIBUTING-source.adoc         ← source
│   ├── CONTRIBUTING.adoc                ← generated
│   └── gesinn-it-docs-master-pub/       ← submodule
└── .github/
    ├── copilot-instructions-source.adoc ← source
    └── copilot-instructions.md          ← generated
----

=== docs/attributes.adoc

Defines project-specific AsciiDoc attributes used by all source files.
This is the single source of truth for project-level variables.

[source,asciidoc]
----
:project_name: MyExtension
:project_type: mediawiki
----

Optional feature flags control which snippets are included:

[cols="1,2,1"]
|===
| Attribute | Effect | Default

| `:phan:`
| Enables Phan static-analysis sections in coding conventions, CI workflow, and Copilot instructions
| off (not set)
|===

Set a flag by adding it to `docs/attributes.adoc`:

[source,asciidoc]
----
:phan:
----

All source files include this file instead of defining attributes inline:

[source,asciidoc]
----
// README-source.adoc
include::docs/attributes.adoc[]
= {project_name}
...

// docs/CONTRIBUTING-source.adoc
include::attributes.adoc[]
include::gesinn-it-docs-master-pub/documents/{project_type}/contributing.adoc[]

// .github/copilot-instructions-source.adoc
include::../docs/attributes.adoc[]
include::../docs/gesinn-it-docs-master-pub/documents/{project_type}/copilot-instructions.adoc[]
----

== Setup

Add as a submodule in the `docs/` directory of the consuming repository:

[source,bash]
----
git submodule add https://github.com/gesinn-it-pub/gesinn-it-docs-master-pub docs/gesinn-it-docs-master-pub
git submodule update --init
----

Reference content in source files:

[source,asciidoc]
----
\include::docs/gesinn-it-docs-master-pub/sections/universal/semver-policy.adoc[]

\include::docs/gesinn-it-docs-master-pub/snippets/mediawiki/coding-conventions-php.adoc[]

// embed a section one level deeper:
\include::docs/gesinn-it-docs-master-pub/sections/mediawiki/architecture-conventions.adoc[leveloffset=+1]
----

Update to the latest version:

[source,bash]
----
git submodule update --remote docs/gesinn-it-docs-master-pub
git add docs/gesinn-it-docs-master-pub
git commit -m "deps(docs-master): update submodule"
----

== Generating output files

Repositories using shared documentation snippets often maintain two README files:

----
README-source.adoc
README.adoc
----

`README-source.adoc` is the editable source file and may contain `include` directives referencing snippets from this repository.

GitHub does not resolve AsciiDoc `include` directives when rendering documents. Therefore the README must be flattened before it can be displayed correctly.

This is done using https://github.com/asciidoctor/asciidoctor-reducer[asciidoctor-reducer].

----
README-source.adoc
        ↓
asciidoctor-reducer
        ↓
README.adoc
----

The generated `README.adoc` is committed to the repository so that GitHub displays the fully expanded documentation.

IMPORTANT: `README.adoc` is a generated file and should not be edited manually.  
All changes must be made in `README-source.adoc`.

== GitHub Actions integration

All documentation is generated by a single `build-docs.yml` workflow.
Running all generations in one job and committing once eliminates parallel-commit race conditions.

The workflow is triggered by changes to any source file, `docs/attributes.adoc`, or the submodule:

[source,yaml]
----
name: Build Docs

on:
  push:
    paths:
      - README-source.adoc
      - docs/CONTRIBUTING-source.adoc
      - .github/copilot-instructions-source.adoc
      - docs/attributes.adoc
      - docs/gesinn-it-docs-master-pub
      - docs/gesinn-it-docs-master-pub/**
    branches:
      - '**'
  workflow_dispatch:

jobs:

  build:
    timeout-minutes: 10
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          submodules: 'true'

      - name: Install tools
        run: |
          sudo apt-get update
          sudo apt-get install -y asciidoctor pandoc
          sudo gem install asciidoctor-reducer --pre

      # --- README ---

      - name: Reduce README
        run: asciidoctor-reducer -o README.adoc README-source.adoc

      - name: Add autogenerated header (README)
        run: |
          printf "// THIS FILE IS AUTO-GENERATED.\n// Edit README-source.adoc instead.\n\n" | cat - README.adoc > README.tmp
          mv README.tmp README.adoc

      # --- CONTRIBUTING ---

      - name: Reduce CONTRIBUTING
        run: asciidoctor-reducer -o docs/CONTRIBUTING.adoc docs/CONTRIBUTING-source.adoc

      - name: Add autogenerated header (CONTRIBUTING)
        run: |
          printf "// THIS FILE IS AUTO-GENERATED.\n// Edit docs/CONTRIBUTING-source.adoc instead.\n\n" | cat - docs/CONTRIBUTING.adoc > docs/CONTRIBUTING.tmp
          mv docs/CONTRIBUTING.tmp docs/CONTRIBUTING.adoc

      # --- Copilot Instructions ---

      - name: Reduce copilot-instructions source (flatten includes)
        run: |
          asciidoctor-reducer \
            -o .github/copilot-instructions.adoc \
            .github/copilot-instructions-source.adoc

      - name: Convert AsciiDoc to DocBook
        run: |
          asciidoctor \
            -b docbook5 \
            -o .github/copilot-instructions.xml \
            .github/copilot-instructions.adoc

      - name: Convert DocBook to Markdown
        run: |
          pandoc \
            -f docbook \
            -t gfm \
            .github/copilot-instructions.xml \
            -o .github/copilot-instructions.md

      - name: Add autogenerated header (copilot-instructions)
        run: |
          printf "<!-- THIS FILE IS AUTO-GENERATED. Edit .github/copilot-instructions-source.adoc instead. -->\n\n" | \
          cat - .github/copilot-instructions.md > tmp
          mv tmp .github/copilot-instructions.md

      - name: Remove intermediate files
        run: |
          rm -f .github/copilot-instructions.adoc
          rm -f .github/copilot-instructions.xml

      # --- Single commit ---

      - name: Commit generated files
        uses: EndBug/add-and-commit@v8
        with:
          add: |
            README.adoc
            docs/CONTRIBUTING.adoc
            .github/copilot-instructions.md
          pull: '--rebase --autostash'
          message: "docs(ci): update generated documentation [skip ci]"
----

== CI configuration

Repositories typically run tests using a separate CI workflow.

Since documentation generation commits changes to the repository, the CI workflow should ignore documentation-only updates.

Example CI trigger configuration:

[source,yaml]
----
on:
  push:
    branches: [ master ]
    paths-ignore:
      - '**/*.adoc'
      - .github/copilot-instructions.md
  pull_request:
    branches: [ master ]
    paths-ignore:
      - '**/*.adoc'
      - .github/copilot-instructions.md
  workflow_dispatch:
----

This ensures that:

* documentation updates do not trigger the full test matrix
* CI runs only for actual code changes
* Documentation generation commits do not cause unnecessary CI runs

== Rationale

Using shared documentation snippets provides several advantages:

* avoids duplicated documentation across repositories
* ensures consistent wording and structure
* simplifies maintenance of common documentation sections
* allows centralized updates across multiple projects

This approach enables lightweight documentation reuse without requiring a full documentation framework.
