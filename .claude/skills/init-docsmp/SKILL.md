---
name: init-docsmp
description: >
  Initialize a consumer repository with the gesinn-it-docs-master-pub (DOCSMP)
  submodule from scratch. Use when a repository has no docs/ directory, no
  AGENTS-source.adoc, and no build-docs workflow yet. Creates the submodule,
  docs/attributes.adoc, minimal *-source.adoc files, the .claude/ directory,
  and the build-docs.yml GitHub workflow. Safe to run: checks for existing
  files before creating them.
compatibility: >
  Requires git and gh CLI. Target repo must be a GitHub repository.
  The GitHub remote URL must be known (used in build-docs.yml and README-source.adoc).
---

## Context

This skill sets up a consumer repository to use `gesinn-it-docs-master-pub`
as a Git submodule. The submodule provides shared snippets, sections, documents,
and build scripts. Once set up, the `build-docs.yml` workflow auto-generates
`AGENTS.md`, `CLAUDE.md`, scoped instructions, and skills on every push.

---

## Step 0: Gather facts

Before creating anything, collect the required values:

```bash
# Repo root
git rev-parse --show-toplevel

# GitHub remote URL (used in source files)
git remote get-url origin

# Extension/project name from extension.json or composer.json
cat extension.json 2>/dev/null | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['name'])"
# or
cat composer.json 2>/dev/null | python3 -c "import json,sys; d=json.load(sys.stdin); print(d.get('name',''))"
```

You need:
- `PROJECT_NAME` — human-readable name (e.g. `Arrays`)
- `PROJECT_TYPE` — `mediawiki`, `nodejs`, `ansible`, or `factory`
- `PROJECT_ACRONYM` — short identifier derived from the project name (e.g. `SRF` for SemanticResultFormats). Ask the user if not obvious.
- `GITHUB_ORG_REPO` — e.g. `gesinn-it-pub/mediawiki-extensions-Arrays`

If `PROJECT_TYPE` or `PROJECT_ACRONYM` cannot be determined automatically, ask the user.

---

## Step 1: Add the submodule

Check first:

```bash
ls docs/gesinn-it-docs-master-pub 2>/dev/null && echo "already exists"
```

If it does not exist:

```bash
git submodule add https://github.com/gesinn-it-pub/gesinn-it-docs-master-pub docs/gesinn-it-docs-master-pub
git submodule update --init docs/gesinn-it-docs-master-pub
```

---

## Step 2: Create docs/attributes.adoc

Check first: `test -f docs/attributes.adoc && echo "exists"`

If missing, create `docs/attributes.adoc`:

```asciidoc
:project_name: {PROJECT_NAME}
:project_type: {PROJECT_TYPE}
:project_acronym: {PROJECT_ACRONYM}
```

For MediaWiki extensions that use Phan, add a fourth line:

```asciidoc
:phan:
```

Ask the user whether Phan is configured in this repo before adding it.

---

## Step 3: Create AGENTS-source.adoc

Check first: `test -f AGENTS-source.adoc && echo "exists"`

If missing, create `AGENTS-source.adoc` with the minimal boilerplate:

```asciidoc
// ============================================================
// THIS IS THE SOURCE FILE. Edit this file only.
// AGENTS.md is AUTO-GENERATED by the GitHub
// workflow .github/workflows/build-docs.yml.
// NEVER edit or regenerate AGENTS.md manually.
// ============================================================
include::docs/attributes.adoc[]
```

Do **not** add a "Conventional Commits" or "Versioning" section here.
Those conventions are already covered by the `commit-do` and `release-do`
skills and are loaded on demand. Duplicating them in `AGENTS-source.adoc`
would load the same content on every context load, wasting tokens.

Project-specific rules go as additional `==` sections after the header
comment. Leave the file minimal for now — the user can add project-specific
sections later.

---

## Step 4: Create README-source.adoc

Check first: `test -f README-source.adoc && echo "exists"`

If missing, create `README-source.adoc`:

```asciidoc
include::docs/attributes.adoc[]
= {project_name}

image:https://github.com/{GITHUB_ORG_REPO}/actions/workflows/ci.yml/badge.svg[CI,link=https://github.com/{GITHUB_ORG_REPO}/actions/workflows/ci.yml]

TODO: Add project description.
```

If a `README` or `README.md` already exists, copy its content as the
description paragraph — do not discard existing documentation.

---

## Step 5: Create docs/CONTRIBUTING-source.adoc

Check first: `test -f docs/CONTRIBUTING-source.adoc && echo "exists"`

If missing, create `docs/CONTRIBUTING-source.adoc`:

```asciidoc
include::attributes.adoc[]
include::gesinn-it-docs-master-pub/documents/mediawiki/contributing.adoc[]
```

Replace `mediawiki` with the actual `PROJECT_TYPE` if different.

---

## Step 6: Create .claude/ directory

Check first: `test -d .claude && echo "exists"`

If missing:

```bash
mkdir -p .claude
```

Do **not** create `CLAUDE.md` manually. The `build-docs.yml` workflow
generates it via `cp AGENTS.md .claude/CLAUDE.md` on every run — it will
appear after the first CI execution.

---

## Step 7: Create .github/workflows/build-docs.yml

Check first: `test -f .github/workflows/build-docs.yml && echo "exists"`

If missing, create the directory and the workflow file.
Load `references/01-build-docs-workflow.md` for the full workflow template
and substitute `{PROJECT_TYPE}` with the actual project type.

---

## Step 8: Update .gitignore

Ensure these entries are present in `.gitignore` (add if missing, do not
duplicate):

```
node_modules/
vendor/
```

---

## Step 9: Validate

```bash
# Submodule registered
grep "gesinn-it-docs-master-pub" .gitmodules

# Source files present
ls docs/attributes.adoc AGENTS-source.adoc README-source.adoc \
   docs/CONTRIBUTING-source.adoc \
   .github/workflows/build-docs.yml

# DOCSMP snippets reachable (smoke-check one include path)
ls docs/gesinn-it-docs-master-pub/sections/universal/changelog-policy.adoc
```

All six files must exist and the DOCSMP snippet path must resolve.

---

## Step 10: Commit

```bash
git add .gitmodules docs/gesinn-it-docs-master-pub \
        docs/attributes.adoc \
        AGENTS-source.adoc README-source.adoc \
        docs/CONTRIBUTING-source.adoc \
        .github/workflows/build-docs.yml
git commit -m "chore(docs): init gesinn-it-docs-master-pub submodule and source files"
```

Do not stage `AGENTS.md`, `README.adoc`, `.claude/CLAUDE.md`, or anything
under `.claude/skills/` or `.agents/skills/` — those are generated outputs
produced by the `build-docs.yml` workflow and do not exist yet.
